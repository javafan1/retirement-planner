# Phase 6E-P3D1B — Arkansas Analyzer Provenance and Capacity

## Executive summary

**ARCHITECTURE_APPROVAL_REQUIRED.** A bounded couple longevity comparison completed all 100 strategies but produced 18,616 distinct v1 pension evidence rows. Production provenance capture refused the replacement at its 10,000-row limit, before the writer ran. The same run contained 174 distinct pension facts once the strategy and death-scenario links were set aside. Those links must survive Save As and reload for the compact form to preserve the original evidence.

The proposed change is an additive Arkansas analyzer provenance version. It would retain the original v1 format for existing history, add ordered side identities for paired analysis, and bind compact Social Security results to observed Arkansas executions. The approval gate applies to the persisted contract. This phase left production code and all P3D1 files intact.

## Proposed provenance design

Add a version-dispatched v2 to the existing `arkansasExecution` capability. Keep the current analysis envelope and schema-three annual projection components. Keep the v1 reader, writer, digest rules and checks for all existing v1 artifacts. The new version would have two complementary records.

1. **Accepted source binding.** Bind each accepted projection UUID to its exact frozen input digest, canonical annual digest, original jurisdiction and applicable policy provenance. Carry the analysis run UUID and exact request fingerprint. Use the owner’s live revision and projection epoch for publication. Use persisted IDs and digests for restoration and freshness after reopening or Save As.
2. **Observed execution and result binding.** At the worker’s financial reduction boundary, record the candidate occurrence, exact claiming elections, effective context and completed year range. For longevity include the exact survivor and death context and the mapping from derived outcomes to validated continuation carriers or independent executions. Bind the reduced result to the accepted outcome and canonical annual evidence digest. Include a separate status for a proven funding shortage and preserve its funded prefix. Unsupported tax carries the typed issue and tax year. Cancellation and supersession revoke publication without a successful result record.

For deterministic search, bind each compact metric and generation-order occurrence before ranking. Validate the original rank and tie order and bind the configured baseline separately from a baseline evaluated under a request-only death year. Verify full retained details with existing schema-three annual/source checks and the observed execution digest. For compact rows, validate the original selection, execution coverage, recorded result metrics and consistency with the stored ranking. The digest binds the compact result to the worker-validated annual evidence. It does not reconstruct annual data omitted by the retention policy.

For individual mortality, inject the controlled worker engine into the existing integrated path. Preserve the independent nine-age comparison, positive-scenario probabilities, exact end at death year minus one and zero-engine opening snapshots. A failed positive-probability scenario cannot contribute a completed expected value. For couple weighted results, keep the established representative and continuation proofs. Record which occurrences each proved carrier covers and permit reuse only where the existing proof supports it. Keep Social Security Only on its existing calculation and freshness path.

## Paired identity and attribution

| Boundary | Proposed behavior |
| --- | --- |
| Source roles | Freeze Current/A and Baseline/B explicitly on the owner thread. Each side cites its accepted projection UUID, exact source document and annual digest. Equal document or annual digests are valid for distinct projection UUIDs. If both roles cite the same accepted UUID, record both ordered roles and pin that original component once. |
| Effective trial settings | Record each side’s explicit run-only survivor age and effective input digest. Verify that the copied request differs from its accepted source only by the authorized election. Preserve the original source projection and its stored survivor assumption. |
| Execution | Select the engine once for each frozen side at the existing `evaluateSide` boundary. Keep the same sampled world and existing result-reduction logic. An Arkansas side uses its controlled annual proof and an ordinary admitted state uses its existing production engine. Require separate actual execution evidence for both sides. |
| Association and freshness | Validate both ordered source roles and request assumptions at acceptance. On reload, check both canonical original components. A role swap changes which result is current, while the original ordering, component IDs and monetary values remain part of the historical record. Save As rebinds the document owner through the existing component copy and preserves source projection UUIDs. |

The existing persistence verifier indexes Arkansas components alone and equates Arkansas analyzer evidence with an Arkansas primary projection. It also rejects identical primary and alternate UUIDs in the paired reference. V2 needs role-aware validation for both orientations and for the same accepted component in both roles. That includes the unchanged-sidecar fast paths in Save As and swapping, so an ordinary Current with an Arkansas Baseline receives the same verification as the reverse orientation. A state with no approved production route, an input outside the admitted state scope, or a pair without valid accepted components remains explicitly unavailable.

## Pension evidence capacity audit and alternatives

The observer projects each pension receipt from genuine completed annual income sources into a `WeightedPension` row. A row identifies the complete strategy, the two modeled death years, the receipt year, the original pension ordinal, recipient, gross amount, qualification and optional receipt evidence. It is retained to verify source and beneficiary attribution for compact weighted outcomes. It is consumed by analysis payload validation and dependency validation on acceptance and historical restoration, including associated result reads and Save As. The weighted UI displays financial aggregates and does not need a second independent copy of every receipt.

The accumulator is already a `LinkedHashSet`. It removes exact duplicate rows, including identical strategy and mortality attribution. Each retained row then repeats the same pension fact for a different attribution. V1 checks that receipt strategies belong to the payload, that each receipt predates the recipient’s death, and that its source ordinal and original-owner or survivor relationship agree with the frozen projection. The broader payload and projection digests also apply. The capture loop, final acceptance and the v1 record constructor enforce the 10,000-row bound. The codec separately caps raw documents at 32 MiB, gzip at 16 MiB, parser tokens at two million and arrays at 100,000. Gzip savings alone cannot lower in-memory row count or parser work. The probe exceeded the v1 logical bound before any accepted document could be written.

| Alternative | Correctness and provenance | Memory and storage | Cost, compatibility and maintenance |
| --- | --- | --- | --- |
| A. Raise the row limit | Keeps individual rows and their v1 checks. A hard failure at a larger limit can still preserve the previous result. | Memory, payload and parser work continue to grow with distinct strategy × execution context × year × pension receipts. The probe already produced 9.06 MB of receipt JSON alone for 100 of 5,184 standard candidate occurrences. | Small coding change and no structural rewrite. Prior readers still reject documents over their existing limit. Repeated tuning of several budgets would be necessary, and dropping surplus rows to fit would lose provenance. |
| B. Factor exact facts and encode attribution separately | Preserve a canonical dictionary of full pension facts and losslessly encode the observed strategy, mortality context and receipt links. Share ranges or lists only when their exact membership is proved. | The measured 18,616 rows shared 174 facts. Attribution data still consumes space. Bound dictionary size, encoded references, logical coverage and validator work independently. | Add a v2 reader and writer. Require unique canonical data, valid indices, no duplicate or unused references, exact coverage and streaming validation. This adds validation work and code, while eliminating repeated facts and avoiding temporary expansion of the entire graph. Keep v1 history byte-compatible. |
| C. Replace the receipt graph with aggregates or a digest | A digest binds content known to the writer. It cannot establish which dropped recipient, amount or qualification was stored after a reload. Recomputing receipts from accepted sources needs a proof of equivalence and a contract for any explicit or modeled receipt evidence. | Lowest storage for a digest alone. A canonical source representation can be compact, with exceptions and coverage increasing the bound. | Highest validation and maintenance risk if it depends on rerunning historical selection logic or a payroll algorithm. An aggregate alone weakens the existing source checks. Use digest commitments alongside the retained evidence rather than as its replacement. |

**Chosen proposal:** B for the pension evidence, with digests for the candidate execution and result bindings. Use accepted-source pension ordinals and exact annual facts, including optional receipt evidence. Preserve exact strategy and mortality attribution. Validate the graph on the worker and in the v2 reader with separate physical and logical limits. If either budget is exceeded, fail the replacement explicitly and retain the last success. The observed reduction in repeated facts motivates the design. Production-size v2 performance and capacity still require measurement.

## Historical schema, freshness and cancellation

V1 payloads and canonical digests must round-trip unchanged. Early controlled historical artifacts retain their original provenance and stay historical, including fixtures with a carrier state in the frozen inputs. V2 artifacts would use the existing optional `arkansasExecution` envelope member with an explicit version and required v2 fields. A v1-only reader will reject v2 evidence. Before implementation, approve that forward-format boundary and the corresponding requirement for explicit unavailability with preservation of the original file. No migration may recalculate old money, reinterpret v1, rewrite a model input or raise the old limit. Reject unexpected versions and malformed references before allocation or association.

Retain revision, owner and request-ticket checks at the existing owner-thread boundary. Pricing, graph capture, retained-detail verification and digest construction stay on a worker. Check cancellation before work begins, between candidates and scenarios, at existing annual/funding/Roth checkpoints, before and during bounded evidence reconstruction, and again before handoff. The owner must reject obsolete progress, errors and results, including the interval after calculation and before association. Historical freshness requires its original inputs and recorded policy. Current freshness additionally requires the active ordered projection dependencies and current effective request, with the alternative side checked even when the Current is an ordinary state.

For deterministic ranking, a candidate without proved financial metrics retains a failure and no rank. Existing insufficient-funds outcomes retain their distinct stage, amounts and year. A positive weighted scenario with unavailable Arkansas tax cannot be treated as an insolvency or receive partial expected value. Preserve the original treatment of existing standalone Monte Carlo, Social Security-only, and successful weighted reuses.
