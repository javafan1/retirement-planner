## 4. Root cause

The controlled worker threw the conditional-benefit state refusal. The completed future relayed it inside a `CompletionException`. The previous presentation branch recognized typed Arkansas annual tax failures only and assigned the wrapper message to the unwrapped footer. That message contained the original exception's fully qualified Java name. The raw text and lack of a warning were reproduced in P3D2B. The underlying admission decision matched the approved state gate. [P3D2B trace](PHASE-6E-P3D2B-ARKANSAS-CONDITIONAL-INCOME-AND-UI-AUDIT.md#7-why-the-java-class-name-reaches-the-ui)

## 7. Async lifecycle and cancellation

The existing completion is the only publication entry. It checks feedback identity on JavaFX, dismisses progress, and calls the controller's owner-thread terminal method. That method clears the run and checks the existing plan/session ownership, revision, epoch, cancellation and frozen input binding. Only a terminal active failure reaches presentation. Cancellation remains quiet apart from its normal status, and obsolete work cannot provide a warning or new result.

The acknowledgment dialog uses nonblocking `show()` outside the controller lock. A visible JavaFX modal that blocks the owner postpones the warning. Before showing it, the application checks that the stage is still active and reuses the completed request's controller binding, including the exact frozen inputs. A new attempt, source revision, file operation, role replacement, close, or shutdown retires the pending presentation. This preserves the existing Arkansas pension-review flow. [Completion and presentation](src/main/java/com/daviddunn/retirementplanner/ui/MainWindow.java#L1124) · [Controller terminal and presentation checks](src/main/java/com/daviddunn/retirementplanner/ui/controller/ApplicationController.java#L1118)
